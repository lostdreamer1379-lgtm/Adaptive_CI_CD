🧠 How the Intelligence Works

The pipeline runs a detect.js script as its very first step. It scans the repo and emits a JSON profile that every subsequent stage reads from. No project-specific config files are ever needed — the pipeline adapts itself.

Detection signals used
📦 package.json deps → framework 🔒 lockfile type → package manager 🧪 test deps → test framework 🔷 tsconfig.json → TypeScript 🐳 Dockerfile → Docker build ▲ vercel.json → Vercel deploy 🐦 fly.toml → Fly.io deploy 📁 packages/ dir → monorepo
🟢 Making the Live tab actually live

This page can't call GitHub's API directly — its sandbox only allows outbound requests to a few script CDNs, not api.github.com. So real-time status needs a small relay in between: GitHub Actions pushes job status to it, and this page polls or streams from it instead.

cd relay && fly launch --now fly secrets set RELAY_SECRET=$(openssl rand -hex 32) # → gives you https://your-app.fly.dev # Then in your GitHub repo's Actions secrets: RELAY_URL=https://your-app.fly.dev RELAY_SECRET=<same value>

Full details in relay/README.md. Without this setup, the pipeline still runs fine — only the Live tab stays disconnected.

🚀 Quick Start
# 1. Copy the .ci folder and workflow into your project cp -r adaptive-cicd/.ci your-project/ cp -r adaptive-cicd/.github your-project/ # 2. Commit and push git add .ci .github git commit -m "chore: add adaptive CI/CD pipeline" git push # 3. The pipeline auto-detects everything on the next push. # No configuration needed.
💡 Tip: Run node .ci/detect.js locally to see exactly what the pipeline will detect before pushing.
⚠️ Known Limitations

This simulator is for previewing adaptive behavior before you push — it is not live-connected to your actual GitHub Actions runs. Real job output, pass/fail status, and timing only exist in the GitHub Actions tab of your repo. See CAPABILITIES.md for the full list — notably: no blue-green/canary deploys, no automatic rollback, no DB service containers for tests, monorepo detection is file-diff based (not dependency-graph aware), and GitHub Actions is the only supported CI platform.
